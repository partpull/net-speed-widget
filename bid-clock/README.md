# 开标时钟 bid-clock

一个极简的 Electron 桌面挂件：**永远置顶**、**背景透明**，屏幕上只显示一串时间
（时:分:秒）；选好开标时间（两个常用预设 **09:30** / **14:00**，也可以自己用下拉挑
小时和分钟）之后，**到点自动退出**。

```
┌──────────────────────────┐
│         09:28:25         │     ← 只有数字，背景完全透明
└──────────────────────────┘
```

它回答的问题只有一个：**现在到底到没到开标时间？** 所以时间一到，挂件自己消失 ——
不用盯着屏幕算时间，也不用担心看漏。

## 运行

本挂件是 `net-speed-widget` 仓库里的一个子项目，**父项目里已经装好了 Electron**，
所以不用再下一遍 100MB 的二进制，直接跑：

```bat
:: 最简单：双击（自动定位 Node 并启动）
bid-clock\scripts\start.bat
```

或在仓库根目录：

```bash
npm run start:bid           # 启动开标时钟
npm run start:bid -- --dev  # 带 DevTools
npm run check:bid           # 纯逻辑自检（不启动界面）
```

想把 bid-clock 单独搬走也可以，它是个完整的小项目：

```bash
cd bid-clock
npm install                 # 需要自己装 electron（国内可先设 ELECTRON_MIRROR）
npm start
```

## 操作

| 操作 | 效果 |
| --- | --- |
| 鼠标左键按住数字 | 拖动挂件（位置会记住） |
| 拖右下角的小三角 | **等比缩放**：窗口变大变小，数字同步变化，横宽比不变 |
| 右键挂件 | 打开菜单（改开标时间 / 窗口大小 / 退出） |
| 托盘图标左键 | 显示 / 隐藏挂件 |
| 托盘图标右键 | 菜单 |
| 设置窗口里选预设 | 点「09:30（上午）」或「14:00（下午）」，立刻生效并记住 |
| 设置窗口里自定义 | 两个下拉选**小时 / 分钟**，再点「使用这个时间」 |
| 设置窗口 `Esc` / `✕` | 关闭设置（没选过时间则直接退出程序） |

菜单里可以改：

- **开标时间** —— 09:30（上午） / 14:00（下午） / 自定义时间…（勾选状态对应当前用的是哪一个）
- **隐藏悬浮钟 / 显示悬浮钟**
- **窗口大小** —— 小 / 中 / 大（也可以直接拖右下角手柄自由缩放）
- **重置位置** —— 回到主屏右上角
- **始终置顶**
- **退出**

## 行为细节

- 时间读数**每帧都取自本机系统时间**，主进程对齐到「整秒之后」推送一次，
  所以秒数不会越走越偏。
- 显示的是**当天**的开标时刻：到点就退出，不会等到第二天。
- 自定义时间和预设一样只精确到**分钟**：小时下拉是 `00–23`、分钟下拉是 `00–59`，
  选的时候旁边会实时提示「距现在约 1 小时 05 分」或者「今天这个时间已经过了」。
- 选到**今天已经过了**的时间（比如 09:31 才点 09:30）不会被采纳：程序不退出、也不会覆盖
  原有设置，只在设置窗口里提示一句「换一个更晚的时间」，你可以接着改。
- 上次选的时间今天过去之后再启动（例如 12:29 到点自动退出，下午又想改时间），会**直接打开
  设置窗口**并提示重选 —— 不会出现「进不去设置、改不了时间」。
- 到点时会先把数字变成开标时刻本身（红色闪烁，例如 `09:30:00`），
  亮 **1.2 秒**后自动退出 —— 让你确实看到「到点了」，而不是感觉提前消失。
- 最后一分钟数字变**琥珀色**，最后 10 秒与到点变**红色**，余光扫一眼就知道快到了。
- 设置窗口右下角有制作人署名：**CAI JIAXING**。

## 配置

配置文件：`%APPDATA%\BidClock\config.json`

```json
{
  "bidTime": "15:45",
  "alwaysOnTop": true,
  "height": 150,
  "aspect": 3.596217564174107,
  "window": { "x": 200, "y": 200 }
}
```

- `bidTime`：`'HH:MM'`，预设（09:30 / 14:00）和自定义时间都存这里；`null` 表示还没
  选过（启动时先弹设置界面）。
- `height`：挂件高度；宽度 = `height × aspect`，所以只存高度就够。
- `aspect`：宽高比由渲染进程按字体实测出来后写回（不同机器字体度量略有差异，
  实测一次就一劳永逸）。想重置整个配置，删掉这个文件即可。


## 实现要点

**为什么窗口不会变形。** 挂件只有一个自由度 —— 高度：

```
宽度 = 高度 × 宽高比
```

字号用 `vh` 表示（`font-size: <n>vh`），留白用「字号的百分比」表示，
所以窗口一变，字和留白一起等比变化，**不需要在 resize 事件里做任何事**。

宽高比是这么来的：渲染进程用 canvas 量出 `00:00:00` 在 100px 字号下的实际宽度
（再放宽 3% 兜底），推算出「正好把字框住」的长宽比，报给主进程去定窗口尺寸。
这样连字号都是实测的，不会出现字被裁掉或者留一大块空白的尴尬。

**为什么时间只在主进程算。** 界面是「哑」的：主进程每秒（对齐到整秒之后）
推 `{ text, phase }` 过来，界面只负责塞进 DOM。这样「读系统时间」「判断是否到点」
「该不该退出」只有一处实现，不会出现两层逻辑打架。

**为什么缩放要用轮询。** 和父项目一样，拖动/缩放都是渲染进程按下时发一条 IPC，
主进程用 `screen.getCursorScreenPoint()` 每 16ms 轮询位移，松手时结束。
好处是鼠标移出窗口也不丢事件，还带 60 秒兜底定时器，不会出现「卡在拖动状态」。

## 打包成 exe（可选）

`bid-clock` 是独立项目，带上自己的 electron-builder 配置：

```bash
cd bid-clock
npm install
npm run build            # 产出 dist\BidClock-1.0.0-portable.exe + setup.exe
```

## 已知限制

- 只认**当天**的开标时间，不跨天等待（到了 00:00 之后，昨天的目标时间就作废了）。
- 时间取的是**本机系统时间**；机器时间不准，显示和退出也会跟着不准。
- 到点后会自动退出，进程和托盘图标一起消失 —— 这是设计如此，不是崩溃。
- 想改「到点后亮多久」或两个备选时刻，改 `src/schedule.js` 里的
  `DUE_FLASH_MS` / `BID_TIMES` 即可。
